What an AI agent actually is

A plain-English walk from a folder of files to a working agent, using the one I built for myself.

October 2026

If you have used ChatGPT, you have used the engine inside an AI agent. You typed a question, it typed an answer. That is a chatbot. An agent is what you get when you give that same engine a job and let it act: read your email, add a meeting to your calendar, reconcile your bank accounts, check its own work, and ask you before it does anything risky.

The easiest way to understand an agent is to picture a new hire. You would not hand a new hire a laptop and walk away. You would give them a job description, the keys and logins they need, a notebook, a calendar, and some clear limits on what they can do without asking. An agent is built from the same five things. I will walk through each one using Archibald, the agent I built to run my own finances, email and schedule. The examples are real files from it, lightly condensed, published in my public GitHub repository with personal details removed.

Start with something you already know: files

Everything that makes an agent an agent lives in a folder on a computer, as ordinary files. Most of them are plain English. There is no magic box. If you can read a memo, you can read most of an agent.

Archibald runs on a Mac mini on my desk, using an open-source program called OpenClaw that connects the files to an AI model and to my phone. The folder holds instructions, small programs, notes and a schedule. Every part below is one kind of file in that folder.

The new hire's brain

The model

The model is the engine: Claude, ChatGPT or similar. It reads text and writes text, and it is very good at both. On its own, that is all it can do. It cannot open your inbox, it does not remember yesterday, and it does nothing until you type. A model is a brilliant new hire on their first morning, before anyone has told them anything.

The job description

Instructions

The first thing you give a new hire is a description of the job. For an agent, that is a set of instruction files, written in plain English. Archibald has one per job it does, called a skill. Here is part of the one for its to-do list:

Read it like a manager’s memo, because that is what it is. It says what the job is, how to do it, and, just as important, what not to assume. Lines like the last one matter most. Most of what makes an agent dependable is instructions like this, usually written after watching it get something wrong.

The keys and logins

Tools

A new hire with a job description but no logins can only talk about the work. Tools are how an agent acts. A tool is a small program the agent is allowed to run: one that reads email, one that adds a calendar event, one that pulls bank transactions. The model decides which tool fits the request, and the program does the actual work the same way every time.

The notebook

Memory

A model forgets everything when a conversation ends. An agent remembers because it writes things down, in files, and reads them back. Archibald’s notebook has three drawers, so it reads only what a task needs instead of everything it knows:

The short file is read every time, like the sticky note on a monitor. Project notes come out when the topic comes up. The archive stays in the drawer unless I ask about something old.

The calendar

A schedule

A chatbot waits for you. An agent also works on a schedule, like a new hire with recurring meetings on their calendar. Archibald has 162 scheduled jobs: pulling bank and card transactions, sorting email, closing the books each month, checking its own accuracy every week.

Here is something most people do not expect: 161 of those 162 jobs do not use the AI model at all. They are plain programs that follow fixed steps. The model is saved for the parts that need judgment, like reading an email and deciding what it is about. That keeps an agent cheaper, faster and more predictable than handing everything to AI.

The limits

Rules for what it cannot do without asking

Putting it together

Here is one ordinary request, start to finish. Say I text Archibald: “Tell the restaurant I’m running late.”

  • The model reads the message and works out what I want.
  • The instructions tell it to look in my own records first: the calendar event for tonight, my contacts, past emails with the restaurant.
  • The tools read the calendar and find the restaurant’s email address, then draft the note.
  • The notebook supplies the standing rules I have given it for how my emails should read.
  • The limits stop it from sending. The draft lands on my phone with ✅ and ❌.

I tap ✅ and the email goes. Total effort on my side: one text and one tap.

The one-sentence version

An agent is a model with a job description, the keys to do the job, a notebook to remember it, a calendar to do it on, and rules for what it cannot do without asking.

None of those parts is mysterious on its own. The skill is in the details: instructions written after real mistakes, tools that do one job, and limits enforced by code rather than by hope. If you want to see how that plays out over months, I wrote about why I built mine and how it works today.
